# Лабораторная работа №4 — CTE и подзапросы

## Цель работы

Научиться разбивать сложный аналитический запрос на CTE, использовать агрегатные
функции и коррелированные подзапросы для сравнения успеваемости студентов,
курсов и учебных групп.

## Файлы

- [Описание структуры базы](data/schema.sql) — таблицы групп, студентов,
	студенческих карт, курсов, слушателей и оценок.
- [Тестовые данные](data/data.sql) — группы, студенты, записи на курсы и оценки.
- [SQL-запрос](sql/cte_subqueries.sql) — итоговый аналитический запрос.

## Запуск

Скрипты рассчитаны на PostgreSQL. В пустой базе данных выполните DDL, загрузите
данные, а затем запустите запрос:

```sql
\i lab4/data/schema.sql
\i lab4/data/data.sql
\i lab4/sql/cte_subqueries.sql
```

Через командную строку последовательность выглядит так:

```bash
psql -d <имя_базы> -f lab4/data/schema.sql
psql -d <имя_базы> -f lab4/data/data.sql
psql -d <имя_базы> -f lab4/sql/cte_subqueries.sql
```

## Логика решения

Запрос состоит из трёх этапов:

1. `raw_grades` объединяет студентов, записи на курсы и оценки, исключая
	 `NULL`-оценки.
2. `student_stats` считает для каждого студента количество пройденных курсов и
	 средний балл. Оставляются студенты минимум с двумя курсами.
3. `group_stats` вычисляет средний балл по каждой учебной группе.

Затем итоговый запрос:

- соединяет показатели студентов и групп;
- оставляет студентов со средним баллом выше общего среднего и среднего балла
	своей группы;
- коррелированным подзапросом считает количество курсов, где оценка студента
	выше средней оценки по этому курсу;
- сортирует результат по группе, среднему баллу и идентификатору студента.

## Результат

| Поле | Описание |
| --- | --- |
| `student_id` | Идентификатор студента |
| `student` | Имя и фамилия студента |
| `group_code` | Код учебной группы |
| `course_count` | Количество курсов с оценками |
| `student_avg` | Средний балл студента |
| `group_avg` | Средний балл учебной группы |
| `courses_above_course_avg` | Число курсов, где студент выше среднего по курсу |

Средние значения в итоговом выводе округляются до одного знака после запятой.
Повторные оценки учитываются в среднем как отдельные записи, а количество курсов
считается через `COUNT(DISTINCT course_id)`.
