## 1. Генерация тестовых данных (DML)
Для тестирования спроектированной схемы база данных была наполнена синтетическими данными с использованием продвинутой генерации[cite: 12].

Особенности скрипта генерации:
* **Абсолютный рандом:** Даты создания каналов, загрузки видео и написания комментариев генерируются случайным образом с помощью функции `random()`[cite: 12].
* **Пул уникальных названий:** База берет случайное количество видео (от 50 до 70) из заготовленного пула на 100 уникальных осмысленных названий (по 10 для каждой тематики)[cite: 12].
* **Реалистичные связи:** Для создания подписок, лайков и комментариев используются `CROSS JOIN` и генерация серий, чтобы избежать монотонных паттернов и создать органичный разброс данных (например, ~60% вероятность лайка на случайное видео)[cite: 12].

## 🌟 Бонус: Кто именно поставил лайк или оставил комментарий?

Архитектура нашей БД (как и у реального YouTube) подразумевает, что пользователи взаимодействуют с контентом от лица своих **Каналов**, а не напрямую через **Аккаунты**. В таблицах `video_likes` и `comments` хранится только `channel_id`[cite: 12].

Чтобы узнать `email` реального человека (Аккаунта), который совершил действие, необходимо сделать двойной `JOIN`. Ниже приведены примеры таких запросов.

### Узнать email авторов комментариев:
```sql
SELECT 
    a.email AS user_email, 
    c.name AS channel_author, 
    comm.content AS comment_text
FROM comments comm
JOIN channels c ON comm.channel_id = c.channel_id
JOIN accounts a ON c.account_id = a.account_id
ORDER BY comm.created_at DESC
LIMIT 5;
